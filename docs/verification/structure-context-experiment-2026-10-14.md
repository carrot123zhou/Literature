# 实验报告：AI 结构校对“压缩上下文 / 收紧复核范围”（2026-10-14，离线，未部署）

> 结论一句话：**上下文压缩（V1）有明确、低风险的离线输入收益证据；压缩+仅异常复核（V2）在 White Lotus 历史回放上省掉 ~60% 输入且历史两遍零分歧，但质量未证，不能据此宣称可部署。** 本报告不调用任何模型，不使用历史 usage 冒充新请求 usage，不把“两遍一致”当真实正确。

## 1. 范围与边界

- 只读真实库与历史作业审计；文献用 Lead 提供的只读快照；未改真实库/raw，未读/打印密钥。
- 未安装、未启动、未构建生产包、未提交/推送 Git；未调用任何模型（含付费）。
- 生产默认路径未变：本轮仅在 `select_review_targets` 增加默认 `strict_local=True` 的可选参数，默认行为与 `d7a0cbd` 完全一致。
- 复现：`tests/manual/experiments/structure_context_experiment.py`（只读，输出 JSON）；边界回归 `tests/test_structure_context_experiment.py`。

## 4. 历史两遍分歧与复核省略风险（White Lotus，348 全量）

历史两遍 = 第一遍规划（6 请求）与第二遍复核（9 请求），均为真实历史响应回放。

- 规划节点 348 / 复核答案 348，无缺失、无解析失败、无重复冲突。
- **规划与复核在 role / level / parent_id 上完全一致：role_changed=0、level_changed=0、parent_changed=0。**
- V2 相比 baseline 省略复核的 241 项中，**历史两遍分歧为 0**；其中漏标提升、标题降级、父子变化均为 0。
- 省略项构成：paragraph 238 + footnote 3；规划角色 body 232 / furniture 6 / footnote 3；本地判据“仍像标题”仅 4 项，240 项为“短且非散文形态”。第二遍对这些项也没有提出任何修正。
- “未收录小节”仍保留：未收录标题 5 个（`THE WHITE LOTUS…`、`Analysis`、`Abbreviations`×2、`Full titles`），其中 `Analysis` 因低置信/树冲突进入 V2 复核，其余在第一遍即为标题且层级不变，仍留在目录树中，未被删除或降级。
- 两遍共有 2 个父子关系问题（`1.1. Defining the problem`、`1.2. Defining some terminology` 被挂为根）——**两遍都没修**，说明“两遍一致”不等于正确；V2 不会让这两项变差（仍在 V2 复核集内），但也不能修复。
- 人工采纳：White Lotus 作业有 43 条 applied 建议（35 set_level、2 set_title、6 set_type）。落在 V2 省略集的仅 2 条（`blk-p000348-0043`、`blk-p000356-0032`），均为本地对账产生的 `set_type→paragraph` 归一，规划/复核结论一致（body/body），不属于模型复核被省略而丢失的修正；无任何“人工采纳项存在两遍分歧”。

## 5. 结论

**有离线收益证据的：**
- V1（仅压缩上下文）在候选与复核选择完全不变的前提下，White Lotus 总输入 -23.2%、Journal 规划 -32.2%；机制明确（去除跨窗口重复上下文），且不改变复核范围，是当前风险最低的提速杠杆。

**离线收益明确、质量未证的：**
- V2（压缩+仅异常复核）在 White Lotus -59.8% 输入、少 6 次请求，历史回放显示第二遍在该样本没有任何 role/level/parent 修正，省略项零分歧、建议集合不变。但这**不能证明**新提示词/新策略准确率：
  - 单一样本、单一模型、单次历史运行；
  - 两遍一致 ≠ 真实正确（两遍共有 2 个树关系错误）；
  - Journal/Authentic 因候选逻辑版本不同无法回放，而它们未收录标题更多（63/12），风险画像不同；
  - 快照可能已含人工采纳，建议集合对比是近似；
  - 无 tokenizer，token 为估算；历史 usage 不代表新请求。

**不可下结论：** 不能声称 V1/V2 的真实准确率、漏标率或真实总耗时提升已验收；V2 不能直接部署。

## 6. 风险清单

1. **V2 漏查未收录小节**：若第一遍把真实小节误判为正文、而第二遍本会纠正，V2 会省略该复核。White Lotus 历史样本未出现，但 Journal/Authentic 未收录标题更多，风险未覆盖。
2. **上下文压缩改变模型输入**：后续窗口不再有整本目录与全局 overview；虽保留近邻目录、祖先、相邻标题与跨章边界，仍需真实模型验证是否影响层级一致性。
3. **共享错误不被修复**：两遍共有的 2 个父子关系问题在 V2 下仍存在。
4. **并发/预算与本次实验无关**：本轮只测输入开销与复核范围，未涉及并发下的真实服务行为。

- 明确边界：真实 A/B 通过前，默认生产策略保持 `d7a0cbd`（选择性复核 + strict_local）；V1 可作为独立、可回退的上下文压缩选项先小范围验证。

## 9. 最小可审批真实 A/B 方案（供用户决策，未开始；不自动执行）

### 9.1 范围与固定变量

- 单样本：White Lotus（348 候选，历史候选 ID 与当前一致）。不扩展第二模型、不扩到 120 次广泛试验。
- 模型：当前结构与翻译角色绑定的同一服务 `yellowbee` / `qwen3.8-flash-next`（自定义中转，`base_url=http://maas.home.hgh.cn.akafeng.me/v1`，`temperature=0.7`，`max_output_tokens=128000`，`reasoning_style` 未设置=不发送思考字段）。
- 分支：A=baseline（当前 `d7a0cbd` 选择性复核，`strict_local=True`）；B=V1（仅压缩上下文，复核选择同 A）；C=V2（压缩上下文 + 仅异常/高风险复核）。可选 D=全量双遍作上界参照（本轮不建议，非必需）。
- 并发固定为 1（串行），以便把“上下文/复核范围”作为唯一变量，并避免把并发当模型速度；生产默认并发 2 不用于本 A/B 的时长对照。
- 不传 `reuse_job_id`；不复用历史回复。

### 9.2 请求数与硬上限

- 名义请求数：A 13（6 规划窗 + 7 复核批）+ B 13 + C 7 = **33**。
- 成立性：成立的前提是第一遍规划在 A/B/C 下产生相同的复核选择。若压缩上下文改变了规划节点，B/C 的复核批数会变化；A/B 上限为全量 15（6+9），C 上限也为 15。
- 结论：33 是名义值，不是硬上限。建议 **总请求硬上限 60**，其中：名义 33 + 规划变化余量（≤6）+ 输出不可解析时的对半拆批重试余量（`_proofread_batch` 最多二分 3 层，但实验中遇到即记录并人工判断是否继续，不静默放大）。

| 分支 | 请求 | 输入字符 | 输入 token 低/中/高 | 可见输出字符 | 含推理输出 token 低/中/高 |
|---|---:|---:|---|---:|---|
| A | 13 | 363,728 | 90,932 / 165,331 / 227,330 | 85,581 | 32,092 / 77,800 / 133,720 |
| B | 13 | 279,275 | 69,819 / 126,943 / 174,547 | 85,581 | 32,092 / 77,800 / 133,720 |
| C | 7 | 146,177 | 36,544 / 66,444 / 91,361 | 45,300 | 16,988 / 41,182 / 70,780 |
| 合计 | 33 | 789,180 | 197,295 / 358,718 / 493,238 | 216,462 | 81,172 / 196,782 / 338,220 |

- 输入字符来自本轮离线精确测量；token 低/中/高分别按 chars÷4 / ÷2.2 / ÷1.6 估算（混合中英文），**不是 tokenizer 结果**。
- 可见输出字符来自历史响应文本长度（规划 41,957 字符/348 行；复核 167.1 字符/决策 → A/B 按 261 决策、C 按 20 决策），**用历史响应长度估算新输出，不是新 usage**。
- 含推理输出按历史 reasoning 占比折算（约 1.5–2.5× 可见输出）；若该模型默认开启思考，输出费用可能显著高于可见输出。
- **总 token 硬上限建议 1,000,000**（含推理高估 831,458 之上留余量）。

### 9.4 币种金额与硬上限（价格当前缺失，不虚构）

- **缺项**：模型服务 `yellowbee` 的 `input_price_per_million` 与 `output_price_per_million` 均为 `null`（`~/Library/Application Support/Literature/model-services.json`），因此**现在无法给出可信的 USD 金额**。中转站为私有域名 + 非标准模型别名 `qwen3.8-flash-next`，不能按官方 Qwen 价格推断。
- 计费公式：`cost_usd = (input_tokens × P_in + output_tokens × P_out) / 1_000_000`，`P_in/P_out` 为该服务的每百万 token 单价（USD）。
- 假设敏感度（**仅为公式演示，不是实际价格**）：

| 假设 P_in / P_out（USD/百万） | A | B | C | 合计 |
|---|---:|---:|---:|---:|
| 0.10 / 0.30 | $0.0399 | $0.0360 | $0.0190 | $0.0949 |
| 0.50 / 1.50 | $0.1994 | $0.1802 | $0.0950 | $0.4746 |
| 2.00 / 6.00 | $0.7975 | $0.7207 | $0.3800 | $1.8982 |

- 一旦用户/服务方提供真实单价：建议**硬上限 = 3 × 中位估算**（用上表“中”列 + 真实单价计算），取整到美分；并把该上限同时写入项目 `budget_usd`（Settings 里为 USD）。仅在配置了单价时，公共 `RequestCoordinator` 才会在发送前按预算拦截（`BudgetExhausted`，审计 `status=blocked`，不付费）。
- **当前 null 价格下 `budget_usd` 不起硬拦截作用**（`prompt_cost_estimator` 返回 0），因此必须叠加 **实验运行器级请求计数器**（达到 60 即在发请求前中止），这是当前唯一可强制的上限。

### 9.5 在途费用上界

- 并发 = 1 时在途最多 1 个请求；若沿用生产默认并发 2，在途最多 2 个。
- 单请求最坏上界（用于容量评估，不代表预期）：输入按最大单请求字符约 50,681 估；输出以服务 `max_output_tokens=128000` 为上界。即单请求上界 `≈ (input_tokens_max × P_in + 128000 × P_out) / 1e6`；这远高于实际（历史单响应约 100–170 字符/行），但硬上限应以此为准。
- 不因本实验修改 `max_output_tokens`（避免截断假提速）。

### 9.6 旧回复复用限制（必须消除）

- 结构作业仅在传入 `reuse_job_id` 且为“同 kind、失败、`context_key` 一致”时跨作业复用；本 A/B 不传 `reuse_job_id`。
- 进程内 `_structure_cache`（TTL 3600s、上限 400）按 `context_key:request_key` 命中；`context_key` 只含模型配置 + 文档版本，**A/B/C 共享同一 context_key**。经离线核对：**A 的规划第 1 窗与 B、C 的规划第 1 窗逐字相同**（V1 压缩对第 1 窗是 no-op），若在同一进程内按顺序跑，B/C 会命中 A 的缓存响应，把缓存命中当模型速度并污染结果。
- 强制措施：每臂开跑前清空 `literature.structure._STRUCTURE_CACHE` 与 `_STRUCTURE_CACHE_ORDER`，或每臂使用独立 sidecar 进程；并在每臂完成后断言 `audit.reused_requests == 0` 且无 `status=='reused'` 请求。
- 反过来说，若观察到 `reused_requests > 0`，该臂作废重跑。

### 9.7 人工核对清单（小规模 gold，不依赖历史两遍一致）

对 A/B/C 三臂输出，人工逐条核对以下集合（约 30–50 项，覆盖全部未收录标题与历史分歧项）：

1. 未收录标题（White Lotus 5 个）：是否为真实小节标题、层级是否正确、父标题是否为最近的上层标题。
2. 疑似漏标提升（非标题→标题）：是否确实应为标题、层级是否正确。
3. 标题降级（标题→正文/脚注）：是否为误降级。
4. 父子关系：是否指向最近的实际父标题、是否跨章节挂错。
5. 层级调整：编号/目录/语义是否支持。
6. 对每条给三值裁决：正确 / 错误 / 无法判定，并记录依据（目录、编号、原页几何或语义）。
7. 同时记录每臂真实 tokenizer usage（若可）、请求数、逐阶段耗时、`reused_requests`。

### 9.8 明确通过/失败标准

- **B（V1）通过**：gold 集合上 B 与 A 的 role/level/parent 决策逐条一致（V1 只改上下文，期望零差异）；且 B 输入 token < A。任一条不一致 → B 不通过。
- **C（V2）通过**：不得漏掉任一 gold 未收录小节标题；不得引入任一错误降级或跨章挂错；不得省略任一人工确认应采纳的修正；且 C 请求数 < B。任一违反 → C 不通过，保留 baseline+V1。
- **公共前置**：每臂 `reused_requests == 0`；请求数 ≤60；总 token ≤1,000,000；若配置了单价则总费用 ≤ 硬上限（超限即中止，未完成臂不计入结论）。
- **结论措辞**：即使全部通过，也只能得出“在该单样本/该模型/该提示词下，B/C 未观察到质量退化且输入开销下降”；仍不能声称通用准确率或生产总耗时已验证。

### 9.9 为何不扩到 120 次/第二模型

- 33（名义）已能在 White Lotus 上分辨“上下文压缩”与“复核范围收紧”两个独立来源；扩到第二模型或更多文献只增加费用与变量，不能替代人工 gold。先以小样本验证判据与流程，再决定是否扩展。
