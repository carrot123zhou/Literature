# 结构校对：本轮产品核查与验收要求

2026-10-03。范围是 macOS Literature 客户端中 AI 校准、手动校准及二者共享的修订管线。页面保留当前三栏布局：左侧目录与校准、中间原件、右侧结构编辑。本文用于执行与验收，不把浏览器模拟成功视为真实模型或打包客户端验收。

## 已修复的入口与操作问题

| 问题 | 原行为 | 修复后的行为 |
| --- | --- | --- |
| 手动基准入口断路 | 首次进入后输入手动目录仍要求源目录页；界面没有关闭提取的入口 | AI 面板直接选择“从源文件目录页提取 / 使用已确认的目录”；手动模式直接显示编辑器，不要求目录页 |
| 基准有效性不清楚 | 仅凭非空文本启用本地校准，非法 Markdown 可能解析成空目录 | 显示实际识别条数；无有效条目时禁用校准并显示格式提示；允许缩进，过滤空标题 |
| 选择数量不可靠 | Shift 范围及修饰键会将图片等只读块加入计数，实际修改数量不一致 | 只允许标题、正文、列表、脚注进入多选；Shift 跳过图片、表格、公式、代码 |
| 手动批量修改后旧建议仍可采用 | 已人工修改块的 AI 建议仍留在待确认队列 | 批量保存成功后清除目标块的旧建议，与单项修改一致 |
| 标题下拉重复 | 已有标题的当前 H 层级出现两次 | 正文、列表、脚注与 H1–H6 各出现一次 |

| 优先级 | 位置 / 触发 | 用户应获得的结果 | 验收方法 |

| P1 | AI 任务失败仅短暂提示 error；作业面板主要展示 message | 失败原因持续可见，已填写目录和页码保留，可明确再次运行 | 模型超时 / 非法 JSON，等待提示消失后仍能在面板看见失败原因 |
| P1 | 建议卡片只有目标，没有修改前类型与页码 | 展示“第 N 页 · 正文 → H2”等具体变更，点击定位；完成状态显示待确认数量 | 检查补回标题、改级、降正文三种建议是否可直接理解 |

P0 的服务端互斥、版本和批量事务应统一覆盖 AI 自动应用、人工单项、批量与撤销。不要让每个入口分别维护不一致的数据锁。

## 最终交付验收

1. 在隔离项目中打开短 PDF，正文→H2→列表→脚注→正文，各次目录 / Markdown / 修订立即同步；反向撤销精确还原文本、列表内容及类型，重启后回读一致。
2. 多选跨越只读块只改文本结构；批量失败无部分写入；单项和全部撤销正确处理同块多次修订。
3. 选定目录页运行 AI，提取结果只作为基准，建议默认待确认；采用 / 忽略后重启保持决策；陈旧建议不能覆盖新结构。
4. 无原书目录时切换到“使用已确认的目录”，用两条基准跑完整管线；关闭视觉后纯文本服务可运行；不支持视觉或认证失败时保留输入并持续显示错误。
5. 测试前后比对 raw manifest 的哈希完全相同；译文 block/cell ID 不变；四种派生导出读取最新结构。
6. 用真实打包客户端重复以上核心操作；再用获授权短样本与配置模型做一次真实服务验收，分别记录 usage、实际输入、输出建议及人工判断，不将模型自报置信度当作准确率。
