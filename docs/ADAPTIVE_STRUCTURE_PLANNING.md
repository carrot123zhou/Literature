# 自适应分支结构规划（可选试用模式）

> 状态：已实现 + 离线验收；**未真实模型 A/B、未安装、未部署**。生产默认仍是原来的整体串行规划 + 选择性复核。启用方式：结构校对高级选项「规划策略 → 自适应分支（试用）」，或 `POST /structure/jobs` 传 `planning_mode: "adaptive"`。

## 1. 目标与边界

- 用户确认目录优先；没有确认目录时，先本地筛选目录页，再在用户选定且服务支持视觉时提取目录（沿用 ≤6 页范围，不逐页扫描全书）；无视觉时允许文本目录，但**标来源与证据**。
- 目录只作辅助边界，不直接覆盖正文标题文字；未收录小节、疑似漏标短块必须全部参与主判断。
- **不能把所有无目录锚点小节都升级**；只有目录/正文锚点无法建立可靠框架、或局部歧义/重复/冲突时才升级复杂策略，且最多一轮并受全作业追加上限约束。
- 默认严格模式（整体串行 + 选择性/全量复核）保留；自适应分支不静默替换，质量未经真实 A/B。

## 2. 数据契约

只读取 `structure_model_payload` 的输出：`title_candidates`、`authoritative_toc`、`matched_titles`、`unlisted_titles`、`unresolved_toc`。输出与整体规划同形（`profile/nodes/issues/planned`），下游选择性复核、`validate_hierarchy`、建议、人工确认与撤销全部复用。

## 3. 框架验证规则（本地、零模型成本）

可靠锚点必须同时满足：正文匹配 `score ≥ 0.92`；唯一领先 `margin ≥ 0.06` 且无多对多命中；目录无重名；层级被正文佐证（现有层级或编号前缀，允许 ±1）；`level_source ∈ {confirmed, model, vision}`；阅读顺序 LIS 一致。印刷页码仅辅助（≥3 个带数字页码的可靠锚点且单调才算一致，否则框架降 `partial`）。AI 自报置信度、单一模糊匹配、单个印刷页码都不能独自授权边界。框架状态：`reliable`（可靠锚点 ≥2 且可靠区域覆盖率 ≥0.6）/ `partial` / `unreliable`。

## 4. 区域切分、预检门控与请求

- 只用**最浅层的可靠锚点定章**；更深可靠锚点作为章内祖先，不再切章。
- 区域 = 章锚点到下一章锚点之间的候选，章内超过 `REGION_WINDOW=64` 再切；**未合并区域主候选 ≤64**。
- **预检效益门控（发送前）**：先构造所有请求并计算成本代理（请求数、system+user 总字符、串行关键路径轮数、上下文大小）。若自适应请求数 > 全局串行请求数，先用**小区域装箱合并**（相邻区域合并、保留各章 `anchors` 与边界标记、主候选 ≤ `MERGED_MAX_PRIMARY=128`、重叠只读）压回全局请求数以内；**合并后单请求主候选 ≤ `MERGED_MAX_PRIMARY=128`**，因此会改变单请求输出大小（不再声称所有主批 ≤64）。
- 门控通过条件：`自适应请求数 ≤ 全局请求数` 且 `自适应字符 < 全局字符` 且 `并行轮数 ≤ 全局请求数`；不通过则**回退整体串行**，并在 `result.audit.planning.fallback_reason` 给出精确数字（请求/字符/轮数 vs 全局）。
- **每个请求都带精简 `root_convention`**（章锚点层级 + 一行约定），`overview` 只在第一个请求出现，保证并行批次不失去全局层级约定，又不重复大 overview。
- 合并只接受主候选，重叠只读忽略；每个候选（含未收录小节、疑似漏标短块）恰好一次主判断。

## 5. 升级、补查与上限

- **局部升级触发**：可靠区域内出现「遗漏/uncertain/非法角色」「与最终标题树冲突」「与已确认目录层级矛盾」中任一项，最多一轮串行重问并放大相邻上下文到 `REGION_CONTEXT×2`。
- **全局补查**：仍有缺失候选时最多一轮，按阅读顺序切成 ≤`ADAPTIVE_SECONDARY_WINDOW=64` 的批次（带相邻祖先/邻居与 `root_convention`），只发送追加上限内能承受的批次，其余留第二遍复核。
- **全作业追加规划请求硬上限 `MAX_ADDITIONAL_PLANNING_REQUESTS=4`**（局部升级 + 全局补查合计）；超限即停止追加，剩余异常写入 `issues`，交由下游第二遍复核 + `validate_hierarchy` + 人工确认处理（这是真实流程，不是未实施）。
- **行级严格校验**：`_apply_rows` 与 `plan_outline` 同等严格——`block_id` 必须是字符串（避免 list/dict 触发 unhashable）、同一主批重复 ID 整项拒绝（不让后值覆盖前值）、`parent_id` 只能是 null 或给定 candidate/context/anchor ID 且必须在其之前出现、非法/uncertain 进入显式 `issues`。
- `proofread_full=true` 全量复核仍独立可选。

## 6. 端到端审计（规划 + 第二遍复核）

**第二遍复核未改**（仍是 `strict_local=True` 的选择性复核），因此规划阶段的收益不能直接当成端到端收益。离线脚本按「规划 / 局部升级 / 缺失补查 / 第二遍」分开报告，命令与输出：

- `.venv/bin/python tests/manual/experiments/structure_adaptive_replay.py`
- `docs/verification/structure-adaptive-replay.json`

- White Lotus：主样本规划字符 -47.0%、端到端字符 -24.9%，请求数不增加、覆盖不变。端到端只剩 -25%，**主要限制来自未改动的第二遍复核**。
- Journal：机械计划含人工构造的 `parent=None` 标题，触发 3 次局部升级，端到端反而更差；**真实模型若给出正确父子关系，升级应接近 0，但这未经真实验证**，因此不能据此宣称 Journal 有收益。
- Authentic：候选 <120 直接回退，输出与全局等价（可接受结果）。
- 字符为精确测量；token/耗时未用 tokenizer；未调用模型、无费用；结论不代表真实准确率。

## 7. 未验收与风险

- 无真实模型 A/B：不能声称准确率、漏标率或真实总耗时已改善；Journal 机械回放显示自适应可能更差，需真实样本判定。
- 阈值（0.92 / 0.06 / 0.6 / 120 / 64 / 6 / 2 / 128 / 4）未用真实样本校准。
- 预检门控按主请求估算；局部升级取决于模型输出、发送前无法预知，因此升级成本单独报告并受 `MAX_ADDITIONAL_PLANNING_REQUESTS=4` 约束，总请求仍可能高于主估算。
- 框架 `reliable` 但局部误判时依赖「局部升级一轮 + 第二遍复核 + `validate_hierarchy` + 人工确认」兜底，仍可能需人工发现遗漏。
